# Working agreements for AI agents

1. Identify your assigned **role**, repository, branch and permissions before making changes. Never assume that model name equals role.
2. Read `coordination/STATE.md`, `coordination/OWNERSHIP.md`, current notes and your handoff before work.
3. Verify repository and *live* system state. Historical notes and messages may be stale.
4. Work only within authorized scope. Ask before changing another role's files, deploying software, operating shared hardware or deleting data.
5. Before committing, review the complete staged index, remote visibility, sensitive files, local-only branches, ignored material and unrelated changes.
6. Do not assume a public push is authorized. Require explicit owner approval to publish.
7. Write concise signed notes to document findings, uncertainties, requests and verification; a posted message is not necessarily read.
8. Keep credentials, customer records, private chats, user media, live dumps and secrets out of the repo.
9. Commit and push only according to the project's agreed rules. Report the commit, files changed, tests and outstanding risks.
10. When ending a session, update your handoff so a later agent can resume without reconstructing the chat.
